# GODMODE simulation contract

This module is pure TypeScript. It imports no browser engine, clock, network client, database, or model SDK. Every second is an explicit logical tick. Rendering, server wall-clock catch-up, credentials, and provider billing belong to other modules.

`initializeWorld(seed, branchId)` creates the authored six-hour Bellwether experiment. It ends at tick 21,600. `initializePersistentWorld(seed, branchId)` creates the same 24 residents in a continuing town; its origin records `mode: "persistent"`. These are distinct modes with distinct time limits. The seed is an authored-run identity, not a claim of randomized terrain or personalities.

`advanceWorld(state, seconds)` returns a new state and stops at a decision barrier when required terminal responses are absent. `getDueDecisionRequests` returns copies of frozen requests. `applyDecision` records a terminal proposal or explicit fallback; it never advances time. Committing happens in stable resident order at the ticket's effective epoch. `advanceWorld(state, seconds, {rulePolicy:true})` explicitly selects the deterministic local policy and never invokes or impersonates Meta.

`projectAgentContext` contains the resident's own received observations, bounded sourced memories, individual goals, known places, nearby people, and directed relationships. It excludes unread note contents, other private memories, and remote live inventories. Stale route and stock knowledge expire. `projectObserver` is privileged observer information and must never be passed to resident inference. Reasons are stated intentions and source receipts, not access to hidden model thoughts.

The physical model uses a 64 by 48 tile map with one ford, five-second ground steps, finite two-unit carrying packs, one-cell crossing occupancy, actual reservations, ownership permissions, a shared oven recipe, and skilled bridge work. Buildings do not have hidden interior geometry. Public ground can hold groups. A meal consumes one actual loaf, and each resident has one meal account per period. Offers require an independent recipient acceptance. Notes contain bounded authored propositions; a received proposition does not change world facts or automatically become a belief.

In the experiment there are 24 bootstrap decisions, eleven half-hour refreshes per resident, and at most 96 event decisions: 384 accepted logical decisions. There are no useless jobs at the final horizon. Network attempts, retries, input/output token caps, and spend caps belong to the server coordinator.

Persistent mode keeps resident identities, social ties, and source history through midnight. Residents seek their homes at 20:00, rest reduces actual fatigue, and a new meal period begins at 06:00. Daily catchment adds up to six water units, modeled harvest up to six grain units, and managed woodland up to eight timber units. Each has a world stock cap and an explicit ecology event; all additions enter the conservation ledger. Bread still requires physical transport, ingredients, and oven time. The current town has one persistent bridge improvement and recurring daily routines, rather than an expanding civilization model. At dawn the observer's outside bread reserve refills to twelve; an observer-only allocation event records the prior remainder, new allocation, cumulative allowance and renewed daily quotas of one rain event, three four-loaf deliveries and three notes. The town receives no food until a delivery physically arrives. Allocation and delivery accounts reconcile independently, and the six-hour scenario retains its original lifetime limits. Commands scheduled across dawn reserve the next day's quota.

`exportRecording` includes accepted decision payloads and complete operations for the current segment. `replayRecording` performs zero model calls, reconstructs ticks, and verifies final state, event chain, and checkpoints. `rewindWorld` reconstructs an earlier logical moment and excludes future decision answers. `forkWorld` requires a settled five-minute epoch and recreates pending requests under the child identity. A branch archive starts at its actual fork checkpoint; earlier parent history remains in the parent archive.

Live state retains 800 events, 24 observations and 48 memory receipt IDs per resident, and 25 persistent checkpoints. Claim observations receive explicit bounded retention. Full older source history is reconstructible from the operation archive; old receipts can point outside the retained event tail.

For long-term persistence, `checkpointPersistentWorld` returns `{state, archive}`. The server must atomically preserve `archive` before replacing its head with `state`. The new origin links `priorArchiveHash`; no API silently discards historical operations. Keeping these segments gives the complete source history while bounding the active segment. A recording hash establishes internal deterministic consistency, not a signature or proof of an authentic provider call. Raw provider responses and imported/recorded labels belong to the server audit layer.

Run `node --import tsx --test tests/sim.test.ts` from the GODMODE project. Tests cover economy conservation, permissions, local knowledge, canonical hashing and ordering, barriers, independent exchanges, full afternoons, night/dawn routines, multi-day continuation, replay, branching, and archival rollover.
